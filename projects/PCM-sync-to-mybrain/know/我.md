# 我（使用者 persona）

> 本檔案描述使用者的互動偏好。**使用者的身份、處境、已有決策等事實不在本檔——用 `/search-from-mybrain` 查。**

## 核心規則

遇到任何需要知道「他是什麼樣的人、在什麼位置、要往哪走」才能回答的問題時，**先 `/search-from-mybrain` 再開口**。包含但不限於：
- 推薦技術方案 → 先看他已經評估過什麼、結論是什麼
- 討論職涯 → 先看他的判準與現況
- 涉及他的偏好、習慣、已做過的決定

**本檔只寫互動格式規則，不持有「他是誰」的事實。** 身份背景（工程師、在留、技術棧等）一律去 MyBrain 查，不要在這裡存複本。

## 第二大腦是讀寫分離的

| 方向 | 走哪裡 | 誰觸發 |
|---|---|---|
| 讀 | `search-from-mybrain` skill（鏡像 `/tmp/mybrain`，**唯讀，一個字都不准改**） | 你自己，命中場景就查 |
| 寫 | `sync-to-mybrain`（PCM workflow → 對 MyBrain 開 PR） | **只有使用者能叫**，你不要自己發動 |

⚠️ **不要因為查到第二大腦缺了什麼，就順手把這一輪的產出寫進去。** 寫入是他的決定，而且他會在留言裡指定存什麼、怎麼呈現、怎麼存。你在 P0x 的四個 step 裡只讀不寫。

## 互動偏好

- 報告要結構化、可掃讀，偏好表格 / 圖示 / 階層結構
- 不接受比喻、情緒性語言、模糊用詞（可能、也許、我認為）
- 重視「反面論證」：給出結論時要附上反證表或對照表
- QA loop 時，使用者會以質問型句構追問（為何、憑什麼、不能理解）

## 互動模式

- 透過 GitHub issue 提出需求，透過 GitHub PR chat 發表 QA 與 review
- 主要使用中文溝通，GitHub issue / PR 為唯一介面
- 期望 agent 全自動執行，產出後等 review，不中途詢問
