# 131_R2_step1-intent.md

## 狀況理解

R2 為使用者對 R1 報告的追問。使用者提出 3 個具體問題：

1. **OKF 的定位釐清**：是標準？是 AICodeAgent 可直接用的 skill/MCP？還是其他？
2. **公司場景應用**：若公司已為每個專案維護 DataModel/BusinessLogic，OKF 如何使用、效果為何？
3. **個人場景應用**：能否作為「個人第二大腦的存取介面」？如何以 opencode/claudecode 為例配置？

使用者語氣為質問型（「有問題」開頭），符合 QA 觸發條件。需在 Step 3 產出報告時追加 `## 5. User Q&A` 章節。

## 執行的動作與結果

| 動作 | 目的 | 預期效果 | 實際結果 |
|------|------|----------|----------|
| 讀取 R1 報告 (output/131_OKF.md) | 回顧已產出內容，確認哪些已回答、哪些需補充 | 確認 R1 報告涵蓋 OKF 規格、背景、替代方案 | R1 報告已涵蓋 OKF 規格細節與生態工具，但未回答定位分類、公司/個人實務應用 |
| 讀取 R1 step1 log | 確認前輪意圖理解 | 確認 R1 為全新調研 | 確認 |
| 解析使用者 3 個問題 | 拆解為可執行的調研子任務 | 明確 Step 2 需搜尋的方向 | 3 個問題分別對應：定位分類、公司 DataModel 整合、個人 PKM + agent 配置 |

## 動作結束後的現狀

| 驗證面向 | 驗證內容與方式 | 驗證結果 |
|----------|---------------|----------|
| R1 報告是否已回答這 3 題 | 掃讀 output/131_OKF.md | §3.10 列出生態工具（OKFy MCP server, okf-skills 等），但未明確分類定位；§4 替代方案 DA 表未涵蓋 DataModel/BusinessLogic 場景；無個人配置指引 |
| 使用者提問類型 | 判斷是否為 QA 觸發 | 是。3 題均為質問型句構（「是標準還是...？」「如何用？」「有沒有可能...？」） |
| 需補充的資訊缺口 | 對照 R1 報告與 R2 提問 | 定位分類、公司 DataModel 整合路徑、個人第二大腦配置方案 |

## 其中的決斷點

| 決斷面向 | 可選選項 | 選擇結果 | 選擇理由 |
|----------|----------|----------|----------|
| 問題 1 定位分類 | 僅回答「是標準」vs 給出完整分類框架（標準/格式/工具/生態） | 完整分類框架 | 使用者問「還是其他？」暗示不滿足於二元分類，需給出多維度定位 |
| 問題 2 公司場景 | 僅描述 OKF 功能 vs 給出具體整合路徑（含 DataModel → OKF 轉換、CI/CD 整合、agent 消費流程） | 具體整合路徑 | 使用者問「如何使用以及效果」，需可操作步驟 |
| 問題 3 個人場景 | 僅回答「可以」vs 給出 opencode/claudecode 的具體配置範例 | 具體配置範例 | 使用者明確要求「以 opencode/claudecode 為例」 |
| QA 章節結構 | 3 題合併為一個 QA vs 拆為 3 個獨立 QA | 拆為 3 個獨立 QA | AGENTS.md 規定「同一輪對話含多個子問題時，拆成多個獨立 QA」 |
