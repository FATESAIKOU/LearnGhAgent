# AI Berkshire — AI 时代的價值投資研究框架

> 調研標的：github.com/xbtlin/ai-berkshire
> 調研日期：2026-07-04

---

## 1. 這個技術解決什麼問題？

**AI Berkshire 解決的是「AI 生成的投資分析品質與決策紀律不足」的問題。**

具體來說，直接問 Claude/GPT「幫我分析某公司值不值得買」，會得到一篇「一方面…另一方面…」的平衡分析，最後以「投資有風險，請自行判斷」收尾。這種分析看起來對，但無法拿來做決策，原因在於：

- **不給明確結論**：沒有通過/不通過/灰色地帶的強制分類
- **單一視角**：缺乏多個投資大師方法論的交叉驗證與觀點碰撞
- **無反偏見機制**：AI 容易給出「看起來很對但經不起推敲」的答案
- **數據不精確**：LLM 心算 PE、市值時常出錯（單位混淆、小數點錯位）
- **不可復現**：每次輸出的格式、深度、覆蓋面不一致，無法橫向對比

---

## 2. 這個問題為什麼會發生？（背景）

### 文章中明確提到的原因

1. **LLM 的「平衡回答」傾向**：AI 被訓練成避免極端立場，傾向給出兩面討好的分析，這在投資決策場景中是致命缺陷
2. **LLM 心算不可靠**：PE 算錯一個小數點、市值單位搞混港幣和人民幣，就可能導致錯誤的投資決策
3. **上下文窗口限制**：一個人直接問 AI，上下文窗口是一個；無法同時從多個獨立視角分析同一家公司
4. **缺乏結構化流程**：沒有標準化的研究框架，每次分析的深度和覆蓋面不一致

### 通用技術背景

1. **LLM 的幻覺與過度自信**：大型語言模型在資料充足時傾向於給出「看起來完整」的分析，即使部分數據是推測或填充的
2. **金融數據的單位敏感性**：跨市場（港股/美股/A 股）的市值單位（港幣億 vs 人民幣億 vs 美元億）極易混淆，一個零的差異就是數量級錯誤
3. **價值投資的方法論複雜性**：巴菲特、芒格、段永平、李錄四位大師的視角各有側重，單一 prompt 無法同時模擬四種思維方式並產生觀點碰撞
4. **AI 的龍頭偏好與英文偏好**：大市值公司資料多、分析篇幅長，看起來「更好」；美股資料豐富，A 股港股容易被低估

## 3. 這個技術是如何解決該問題的？

AI Berkshire 採用**三層架構**（Skill 層 / Agent 層 / 工具層）來解決上述問題：

### 3.1 整體架構

```
┌─────────────────────────────────────────────────────┐
│                    Skill 層（18 個入口）               │
│  🔬 深度研究類（5） 📊 財報分析類（2） 🏭 行業篩選（5）│
│  📈 持倉管理類（3） 🧠 思維工具類（3）                │
├─────────────────────────────────────────────────────┤
│                    Agent 層（4 個並行）               │
│  Agent 1    │ Agent 2    │ Agent 3    │ Agent 4     │
│  商業模式   │ 財務估值   │ 行業競爭   │ 風險管理層   │
│  段永平視角 │ 巴菲特視角 │ 芒格視角   │ 李錄視角     │
├─────────────────────────────────────────────────────┤
│                    工具層                            │
│  financial_rigor.py（精確計算/交叉驗證/三情景估值）   │
│  report_audit.py（報告抽檢/15% 隨機抽樣）             │
└─────────────────────────────────────────────────────┘
```

### 3.2 核心機制

#### 機制一：強制給結論，不打太極

每個 Skill 的輸出都要求明確的結論分類：

```
| 策略 | 建議 | 價格區間 |
|------|------|---------|
| 激進型 | 當前價位可建倉 20% | $95-105 |
| 穩健型 | 等回購政策明確後建倉 | $85-95 |
| 保守型 | 不符合 10 年確定性標準，觀望 | — |
```

鏡子測試：5 句話說不完整 = 不買，沒有例外。

#### 機制二：四大師視角對抗

四個視角產生真實的矛盾和張力，而非四份報告的拼接：

```
段永平（商業模式）→ 評分 3.7/5
巴菲特（財務估值）→ 評分 4.4/5  → 巴菲特說「真便宜」
芒格（逆向思考）  → 評分 3.5/5
李錄（長期確定性）→ 評分 2.0/5  → 李錄說「不確定就不買」
```

這種衝突才是投資決策的真實狀態。

#### 機制三：結構化反偏見機制

| 機制 | 解決什麼問題 | 舉例 |
|------|------------|------|
| 信息豐富度評級（A/B/C） | 防止「資料多=確定性高」的幻覺 | 泡泡瑪特評為 B 級：數據有限，推算指標標註置信度 |
| 芒格式逆向檢驗 | 強制思考失敗場景 | 「什麼情況下拼多多會死？」→ 列出 5 大情景及概率 |
| 快速否決清單 | 8 條紅線一票否決 | 管理層誠信污點 → 直接否決，不管估值多便宜 |
| 反共識檢查 | 避免和市場想法一樣 | 「聰明人為什麼在做空？」→ 發現被忽視的風險 |
| 留白原則 | 寧可說「不知道」 | 數據不足時標註「灰色地帶」，不用推測偽裝確定性 |

#### 機制四：金融數據的精確性

所有計算使用 Python `decimal.Decimal`（精確十進制），不用 `float`：

```bash
# 市值手算校驗：股價 × 總股本，與報告數據對比
python3 tools/financial_rigor.py verify-market-cap \
  --price 510 --shares 9.11e9 --reported 4.65e12 --currency HKD
# ✅ 驗證通過, 偏差僅 0.08%
```

工具層提供 6 個子命令：

| 功能 | 命令 | 解決的問題 |
|------|------|-----------|
| 市值驗算 | `verify-market-cap` | 股價×總股本精確計算，檢測單位錯誤 |
| 估值驗算 | `verify-valuation` | PE/PB/ROE/FCF Yield 精確十進制計算 |
| 多源交叉驗證 | `cross-validate` | N 個來源的同一數據自動比對，超過容差告警 |
| 三情景估值 | `three-scenario` | 樂觀/中性/悲觀精確計算目標價 |
| Benford 定律檢測 | `benford` | 檢測財務數據首位數字分佈異常 |
| 精確計算器 | `calc` | 任意財務表達式精確計算，替代 LLM 心算 |

#### 機制五：可復現的研究流程

18 個 Skill 各自有標準化的執行流程，確保「同樣的輸入 → 結構一致、深度一致的輸出」：

```
/investment-checklist 騰訊, 阿里巴巴, 美團, 拼多多

| 公司 | 通過? | 能力圈 | 好生意 | 護城河 | 管理層 | 安全邊際 | 綜合 |
|------|:-----:|:------:|:------:|:------:|:------:|:-------:|:----:|
| 騰訊 | ✅ 通過 | ★★★★★ | ★★★★★ | ★★★★★ | ★★★★★ | ★★★★☆ | 4.7 |
| 拼多多 | ❓ 灰色 | ★★★★☆ | ★★★★☆ | ★★★☆☆ | ★★★☆☆ | ★★★★★ | 3.8 |
```

#### 機制六：多 Agent 並行

`/investment-team` 啟動 4 個獨立 Agent **同時**研究一家公司。每個 Agent 各自搜索網絡、交叉驗證數據、獨立給出結論：

```
┌─────────────────────────────────────────────┐
│              Team Lead (你)                  │
│         統籌協調 · 匯總研判                  │
├──────┬──────┬──────────┬───────────┤
│ Agent 1    │ Agent 2    │ Agent 3    │ Agent 4     │
│ 商業模式   │ 財務估值   │ 行業競爭   │ 風險管理層   │
│ 段永平視角 │ 巴菲特視角 │ 芒格視角   │ 李錄視角     │
└──────┴──────┴──────────┴───────────┘
        ↓ 並行研究，實時匯報進度 ↓
              最終綜合報告
```

## 4. 是否存在解決類似問題的其他技術 / 框架 / 思考方式？

### DA 表：替代方案對照

| 技術名 | 技術解法 | 技術使用前提 | 技術使用副作用 | 技術使用預期效果 |
|--------|---------|-------------|---------------|-----------------|
| **直接問 LLM**（Claude/GPT 單一 prompt） | 用一個 prompt 要求 AI 分析公司 | 有 LLM 客戶端即可 | 輸出格式不固定、無多視角碰撞、數據可能出錯、結論模糊 | 快速但不可靠，適合初步了解，不適合決策 |
| **傳統券商研報** | 分析師人工撰寫深度研究報告 | 有券商帳戶、分析師覆蓋該公司 | 時效性差（出報告時股價已變）、分析師利益衝突（投行業務）、覆蓋面有限 | 深度夠但覆蓋少、有利益衝突、更新慢 |
| **量化因子模型**（如 Fama-French、Barra） | 用統計模型篩選符合特定因子的股票 | 需要程式設計能力、數據源、回測平台 | 忽略定性因素（管理層、護城河）、過度擬合風險、市場結構變化時失效 | 系統化但缺乏深度，適合篩選不適合決策 |
| **FinBERT / 情感分析工具** | 用 NLP 分析新聞/財報情感分數 | 需要 NLP 基礎設施、訓練數據 | 情感≠基本面、噪音信號比低、無法理解商業本質 | 輔助性強但無法替代基本面分析 |
| **Bloomberg Terminal / Wind** | 專業金融終端提供數據+分析工具 | 年費數萬美元、需要專業培訓 | 成本極高、學習曲線陡峭、仍依賴人工判斷 | 數據最全但分析深度取決於使用者 |

### 切入點差異分析

| 切入點 | AI Berkshire | 直接問 LLM | 券商研報 | 量化模型 |
|--------|-------------|-----------|---------|---------|
| 多視角碰撞 | ✅ 四大師強制對抗 | ❌ 單一視角 | ❌ 單一分析師 | ❌ 無視角 |
| 結論明確性 | ✅ 強制通過/不通過 | ❌ 平衡分析 | ⚠️ 通常模糊 | ✅ 買入/賣出信號 |
| 數據精確性 | ✅ 工具驗算 | ❌ LLM 心算 | ✅ 分析師核對 | ✅ 程式計算 |
| 可復現性 | ✅ 標準化流程 | ❌ 每次不同 | ⚠️ 模板化 | ✅ 固定模型 |
| 定性分析深度 | ✅ 管理層/護城河 | ⚠️ 表面 | ✅ 深度 | ❌ 無 |
| 成本 | 免費（開源） | 低（API 費用） | 高（佣金） | 中（數據+開發） |
| 覆蓋面 | 任意上市公司 | 任意公司 | 僅覆蓋公司 | 指數成分股 |

### 結論

AI Berkshire 的核心差異在於：它不是一個「更好的 AI 分析工具」，而是一個**將價值投資方法論系統化、結構化、可程式化驗證的研究框架**。它解決的不是「能不能分析」，而是「分析品質和決策紀律」的問題。與其他方案相比，它在**多視角碰撞**、**結論明確性**、**數據精確性**、**可復現性**四個維度上同時達到了較高水準，而這四個維度在傳統方案中往往無法兼得。
