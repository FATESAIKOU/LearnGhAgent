# 1on1（一對一管理對談）作為管理手法 —— 以 SmartHR チーフ山下之觀點為骨架

> 標的：SmartHR Tech Blog 文章「2年かけてたどり着いた1on1の形 —— メンバーと一緒に1on1の最適解を探る」（2026-08-13，チーフ山下）。
> 本報告以原作者觀點為骨架，輔以外部參考（SmartHR 相關文章、CEO 芹澤「1on1の功罪」、リクルートMS 等）與使用者第二大腦對照。

---

## 1. 這個技術解決什麼問題？

**1on1 是管理者（チーフ／EM）用來「讓成員能氣持ちよく働ける（舒適地工作）」的定期一對一對談機制。** 它解決的具體問題是：**管理者無法單靠正式會議、目標確認或成果檢核，掌握成員的狀態、動機與阻礙，因而無法讓成員在最佳狀態下產出。**

從作者觀點，1on1 要解決的問題可拆成三層：

| 層級 | 被解決的問題 | 作者原文依據 |
|---|---|---|
| **成員層** | 成員的動機、不安、阻礙沒有被看見，導致無法「氣持ちよく働ける」 | 「メンバーがモチベーションを上げられる何かを一緒に見つけていったり、日々の業務を阻害する何かを取り除いてあげたりすること」 |
| **管理者層** | 管理者不知道成員狀態，只能靠一廂情願的教導／控制，反而壓縮成員自主性 | 「こちらの一方的な働きかけは、むしろメンバーの選択肢を狭め、自主性を損ないます」 |
| **制度層** | 制度只規定「隔週 1on1」，但沒有定義「怎麼做」，管理者無所適從 | 「何を話せばいいのかわからない、メンバーにとって有意義な時間になっているのだろうか？」 |

**問題的模糊之處**：作者把 1on1 的目標定義為「成員能氣持ちよく働ける」，這是一個**開放式、狀態性目標**，不是可量化的成果目標。它不回答「氣持ちよく働ける」如何被測量、多久達成、與團隊產出之間是否存在可驗證的因果。作者自己也承認「1on1 的絕對正解不存在」，因此這個「問題」的邊界是模糊的——它更像一個持續調校的狀態，而非一次可解決的缺陷。

## 2. 這個問題為什麼會發生？（背景）

### 文章明確提到的背景

| 背景 | 內容 |
|---|---|
| **制度規定** | SmartHR 制度上規定「評価者與被評価者隔週 1on1」，即 1on1 是**強制性、有頻率下限**的制度，不是管理者可選的選項 |
| **チーフ角色** | チーフ＝プレイングマネージャー（帶隊且動手），核心任務是「チームの成果を最大化する」，1on1／評価皆為其手段 |
| **成員屬性** | SmartHR 成員是「プロフェッショナル、主體的に業務に取り組む」，因此教導／控制無效 |
| **初期困境** | 作者剛當チーフ時「苦手意識」「何を話せばいいのかわからない」，把 1on1 當成「解決問題、促進成長」的高門檻場合 |

### 通用技術背景（文章未明說，屬管理學脈絡）

| 背景 | 說明 |
|---|---|
| **管理資訊單向壟斷** | 正式會議、目標檢核、成果報告都是「成員→管理者」的單向資訊流，管理者看不到成員的動機、不安、阻礙等非正式狀態 |
| **成果與狀態的斷層** | 成果（output）是落後指標，狀態（動機、阻礙）是領先指標；只看成果無法及早介入 |
| **制度化與方法論的空白** | 制度規定「要做 1on1」，但沒有規定「怎麼做」，方法論留給個人摸索，導致新手管理者無所適從 |
| **權力不對稱** | 管理者握有評價權，成員在正式場合難以坦露真實狀態，需要一個「非正式、低風險」的場域 |

## 3. 這個技術是如何解決該問題的？

作者的做法是**把 1on1 從「管理者單向教導的場合」重構成「與成員共同設計、定期檢驗的場合」**。核心是三大スタンス＋場的設計＋進め方＋振り返り。

### 3.1 三大スタンス（作者的原則）

| スタンス | 內容 | 對應解法 |
|---|---|---|
| **① 最終ゴール＝成員能氣持ちよく働ける** | 1on1 不是教導／控制，而是「找出能提升成員動機的事、移除阻礙業務的事」 | 把目標主語放在成員身上，管理者不預設要教什麼 |
| **② 重視アイスブレイク** | 場的空氣決定話的廣度與本音數量 | 用定型文「最近の調子は10点満点中何点？」開場 |
| **③ 定期讓成員評價 1on1 並改善** | 目標主語是成員，管理者自評不可信，需直接聽成員聲音 | 四半期一次振り返り，聚焦提問 |

### 3.2 場的設計（初回 1on1 與成員一起設計）

```
初回 1on1
  ├─ ①「1on1 對你來說是什麼樣的時間會開心？」→ 收集成員需求
  ├─ ② 目的確認與調整（用たたき台當起點）
  ├─ ③ アジェンダ整理（定例＋特別アジェンダ）
  └─ ④ 頻度與時間設定（預設隔週 30 分，依成員調整）
```

**目的たたき台**（作者提供，依成員調整）：

| 面向 | 目的 |
|---|---|
| 成員 | 不安解消或找到解消的第一步；成長實感或得到成長線索 |
| チーフ | 掌握成員是否無理なく働けている；掌握目標達成所需的支援與障礙；取得多角度看團隊的資訊 |

### 3.3 進め方（每次 1on1 的流程）

```
アイスブレイク（5-10 分）
  └─ 定型文「最近の調子は10点満点中何点？」
       ├─ 高分 → 掘り下げ要因（「8点ですね、最近何かいいことありましたか？」）
       └─ 低分 → 從業務負荷／動機下降視角掌握團隊課題
本題
  ├─ 先確認成員持ち込みトピック（專案進捗、課題感、困っていること、不安）
  └─ 無持ち込み時 → チーフ提問（見下表）
收束判準
  └─ 成員是否前向きに業務に向き合える狀態？成員／團隊有無問題？
```

**チーフ提問範例**（成員無持ち込み時）：

| 提問 | 目的 |
|---|---|
| 這個 A 專案，你有不安的地方嗎？ | 掌握專案風險與成員焦慮 |
| 目前團隊在推的 B 方案，你納得度如何？有在意的地方嗎？ | 掌握團隊決策的接受度 |
| 對一起工作的成員，有想 feedback 的事嗎？ | 取得正式場合說不出口的資訊 |
| 現在想要的支援是什麼？ | 直接取得阻礙清單 |

### 3.4 振り返り（定期檢驗 1on1 本身）

四半期一次，聚焦提問（避免「1on1 如何？」這種太開放、難以回答的問法）：

| 提問 | 目的 |
|---|---|
| 1on1 中動機上升／下降的時機？ | 找出有效與無效的環節 |
| 1on1 中更想多談的事？ | 找出アジェンダ缺口 |
| アジェンダ想改的地方？ | 調整定例內容 |
| 頻度、時間是否適切？ | 調整頻率與長度 |

**作者結論**：1on1 無絕對正解，但「兩人間有最適解」，靠定期振り返り與成員一起探索。

## 4. 是否存在解決類似問題的其他技術 / 框架 / 思考方式？

「讓成員在最佳狀態下產出」這個目的，除了 1on1 之外，還有其他切入點。以下 4 個替代方案，從「狀態／能力／行為／成果」四個軸切入，切入點不同。

### 4.1 替代方案與 DA 表

| 技術名 | 技術解法 | 技術使用前提 | 技術使用副作用 | 技術使用預期效果 |
|---|---|---|---|---|
| **1on1（作者形式）** | 定期一對一對談，與成員共同設計場、定期振り返り，聚焦「狀態」 | 管理者有時間與對談能力；成員願意坦露；制度允許頻率彈性 | 若淪為ヒアリング（單向蒐集資訊）的場合則失去對談價值；頻率過高耗時 | 掌握成員狀態、動機與阻礙，讓成員氣持ちよく働ける |
| **コーチング（coaching）** | 以提問引導成員自己找到答案，聚焦「能力／自主性」 | 管理者受過 coaching 訓練；成員有自我探索意願 | 對需要明確指示的新人無效；管理者需克制給答案的衝動 | 提升成員自主解決問題的能力，長期降低依賴 |
| **フィードバック（feedback）** | 定期、具體地回饋行為與成果，聚焦「行為」 | 有可觀察的行為或成果；管理者能給具體、非人身攻擊的回饋 | 若頻率過高或方式不當，易造成防衛心；需要信任基礎 | 修正行為、提升績效，讓成員知道該往哪調整 |
| **目標管理（OKR 等）** | 設定可量化目標與關鍵結果，聚焦「成果」 | 環境可預測；需要跨部門對齊；目標可量化 | 邊際效益遞減、短視近利、目標錯誤時產生沉沒成本 | 資源集中、特定期限內產出可見成果 |

### 4.2 切入點差異

| 軸 | 切入點 | 代表方案 |
|---|---|---|
| **狀態** | 掌握動機、不安、阻礙等領先指標 | 1on1（作者形式） |
| **能力** | 提升成員自主解決問題的能力 | コーチング |
| **行為** | 修正具體行為與績效 | フィードバック |
| **成果** | 設定並追蹤可量化目標 | 目標管理（OKR） |

## 5. User Q&A

### Q1：作為管理者，在「掌握成員動機、不安、阻礙」這個目的上，除了 1on1 沒有其他做法嗎？1on1 本身的目的與「有沒有更優選項」為什麼沒解說？

**A**：有。1on1 只是「掌握成員狀態」此一目的的一種機制，不是唯一。R1 §4 只列了「替代方案」而未解說「1on1 的目的」與「是否最優」，此缺口成立。以下把「掌握狀態」此一目的單獨拆出，跨機制比較。

**「掌握狀態」此一目的下的機制光譜**（依資訊取得方式分類）：

| 機制 | 資訊來源 | 掌握什麼 | 前提 | 副作用 | 預期效果 |
|---|---|---|---|---|---|
| **1on1（作者形式）** | 成員本人，一對一對談 | 動機、不安、阻礙、狀態 | 管理者有對談能力；成員願坦露；制度允許頻率彈性 | 若淪為ヒアリング（單向蒐集）則失去對談價值；頻率過高耗時 | 掌握個別成員狀態，讓成員氣持ちよく働ける |
| **skip-level meeting** | 下屬的下屬（越過直屬） | 被中間管理者過濾掉的真實資訊 | 組織允許越級對談；不破壞中間管理者信任 | 削弱中間管理者信任；需拿捏分寸 | 取得被過濾的底層真實狀態 |
| **360 feedback** | 上下左右多向回饋 | 行為與狀態的多角度樣貌 | 有信任基礎與匿名性 | 若未行動於洞察則淪為「抽屜問卷」 | 多向掌握，補單一視角盲點 |
| **engagement survey／pulse survey** | 團隊整體量化 | 團隊整體狀態、趨勢 | 問卷設計良好 | 頻率過高造成問卷疲勞；只能掌握整體難掌握個人 | 量化掌握團隊狀態趨勢 |
| **觀察（MBWA／日常互動）** | 日常協作、會議、工作產出 | 行為與狀態的側面 | 管理者有觀察時間 | 主觀、易漏、易誤判 | 低成本掌握，但精度低 |
| **coaching** | 成員本人，以提問引導 | 成員自我探索出的狀態 | 管理者受過 coaching 訓練 | 對需明確指示者無效；需克制給答案 | 間接掌握狀態，同時提升成員自主性 |

**「1on1 是否為最優」的判準**：作者觀點下，1on1 的不可替代性在於**同時滿足「一對一」「低風險坦露」「可持續調校」**三條件——skip-level 有信任風險、survey 只能掌握整體、觀察精度低、coaching 需訓練。但「最優」是**依目的與情境**的相對判斷，不是絕對：

| 情境 | 較優機制 | 理由 |
|---|---|---|
| 掌握個別成員深層動機／不安 | 1on1 | 一對一、低風險、可追問 |
| 掌握被中間層過濾的底層真實 | skip-level | 越過過濾層 |
| 掌握團隊整體狀態趨勢 | survey | 量化、可比較 |
| 掌握多角度行為樣貌 | 360 feedback | 多向交叉 |
| 低成本日常掌握 | 觀察 | 零額外成本 |

**結論**：1on1 是「掌握個別成員狀態」此一目的下的**主要機制，但不是唯一機制**。作者文章聚焦「如何做好 1on1」，故未解說「1on1 的目的」與「是否最優」——此為文章範圍限制，非機制本身缺陷。選擇哪個機制取決於「要掌握誰的狀態、多深、多頻」。

### Q2：作為後進的資深員工（之後可能接管理），要如何掌握周邊成員的狀態，甚至上級的狀態？

**A**：此視角與 Q1 的管理者視角不同——主體是**準管理者（資深 IC）**，對象是**同儕與上級**，且**沒有權力不對稱的優勢**（對上級尤其如此）。掌握方式分「同儕」與「上級」兩條軸。

**同儕狀態的掌握**（無權力不對稱，靠信任與互惠）：

| 方式 | 掌握什麼 | 前提 | 副作用 |
|---|---|---|---|
| 協作專案／code review | 同儕的技術狀態、負荷、風格 | 有共同協作場景 | 僅限工作面向 |
| 跨團隊專案 | 同儕在更大脈絡下的狀態 | 有跨團隊機會 | 頻率低 |
| 日常互動 | 同儕的動機、壓力、阻礙 | 有信任基礎 | 主觀、易漏 |

**上級狀態的掌握**（上級握有資源與決策權，需主動建立關係）：

| 方式 | 掌握什麼 | 前提 | 副作用 |
|---|---|---|---|

### Q3：把文章提到的 1on1 技法總結成表格（技法名、技法詳細、技法效果/目的）

**A**：以下從原文萃取，欄位＝技法名／技法詳細／技法效果目的。共 7 項技法。

| 技法名 | 技法詳細 | 技法效果／目的 |
|---|---|---|
| **① 10 點體調分數アイスブレイク** | 每次 1on1 開場用定型文「最近の調子は10点満点中何点？」；高分掘り下げ要因（「8点ですね、最近何かいいことありましたか？」），低分從業務負荷／動機下降視角掌握 | 建立場的空氣、持續掌握成員體調與狀態、讓成員自我回顧 |
| **② 目的たたき台** | 初回 1on1 提供目的たたき台（成員：不安解消／成長實感；チーフ：掌握狀態／支援障礙／多角資訊），依成員調整 | 讓「1on1 目的」有起點可討論，避免成員無從想像 |
| **③ アジェンダ整理（定例＋特別）** | 定例アジェンダ＝アイスブレイク＋調子分數＋話したいこと；依成員需求設特別アジェンダ（月1目標進捗、3ヶ月1度キャリア等） | 讓每次 1on1 有結構，同時保留彈性 |
| **④ 頻度與時間設定** | 初回確認成員希望的頻度與時間；預設隔週 30 分，依成員與團隊狀態調整（立ち上がり期每週、穩定期隔週） | 讓 1on1 頻率與長度符合成員需求 |
| **⑤ 持ち込みトピック優先** | 本題先確認成員有無想談的事（專案進捗、課題感、困っていること、不安） | 確保 1on1 是成員的場，而非管理者單向 |
| **⑥ チーフ提問範例** | 成員無持ち込み時，用固定提問：專案不安？方案納得度？對成員想 feedback 的事？想要的支援？ | 從正式場合說不出口的面向取得資訊 |
| **⑦ 四半期振り返り聚焦提問** | 每季一次，用聚焦提問（動機上升／下降時機、更想多談的事、アジェンダ想改處、頻度時間是否適切）而非開放式「1on1 如何？」 | 定期檢驗 1on1 本身並改善，避免開放式問題難回答 |

**技法間的關係**（原文的組裝邏輯）：

```
初回 1on1（設計場）
  ├─ ② 目的たたき台
  ├─ ③ アジェンダ整理
  └─ ④ 頻度時間設定
每次 1on1（執行）
  ├─ ① 10點調子アイスブレイク
  ├─ ⑤ 持ち込みトピック優先
  └─ ⑥ チーフ提問（無持ち込み時）
定期（檢驗）
  └─ ⑦ 四半期振り返り聚焦提問
```

**結論**：原文 7 項技法分三層——**設計場**（②③④）、**執行場**（①⑤⑥）、**檢驗場**（⑦）。核心邏輯是「先與成員共同設計場，再執行，再定期檢驗」，與作者「1on1 無絕對正解、靠定期振り返り與成員一起探索」的結論一致。
