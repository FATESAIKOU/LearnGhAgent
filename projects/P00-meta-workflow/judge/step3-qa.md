# Step 3 - 品質保證 Review 觀點

> 軟性驗證 Step 3 分析報告產出時，LLM 應採用的 review 觀點。

## 驗證項目

| 項目 | 結果 | 備註 |
|------|------|------|

1. **4 個 section 齊全**：§1 問題、§2 背景、§3 解法、§4 替代方案 是否都存在？
2. **DA 表存在與完整**：§4 是否含 2～4 個替代方案的 DA 表？欄位是否齊全（技術名、技術解法、技術使用前提、技術使用副作用、技術使用預期效果）？
3. **語言合規**：是否使用中文？是否避免比喻、情緒性語言、模糊用詞（可能、也許、我認為）？
4. **結構化呈現**：是否使用表格、圖示、階層結構強化心智模型？
5. **反面論證**：是否含反證表或對照表強化論證？
6. **報告檔名**：是否符合 `(pr-id)_(技術名).md` 格式？長度是否在限制內？
7. **第二大腦對照**：生成的 `judge/` 卡的鬆緊，是否對照過 MyBrain 裡他對 agent 信任邊界與自動化程度的準則（骨幹、抽象理解/本質洞察）？引用是否帶 GitHub URL 與信任層級？查不到而明寫第二大腦沒有也算通過；沒查或編造一律 FAIL。
8. **MyBrain 接線是否被複製過去**：生成的 `<project_name>.yml` 是否保留了 `Setup MyBrain search` step，以及 Step 1／Step 3 的查第二大腦指示？漏掉的話新 project 就查不到他的脈絡，一律 FAIL。
