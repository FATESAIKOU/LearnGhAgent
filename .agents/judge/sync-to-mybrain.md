# sync-to-mybrain Review 觀點

> 軟性驗證 sync-to-mybrain 產出時，LLM 應採用的 review 觀點。
> 與 `projects/*/judge/step*.md` 同型：這裡定義的是「怎麼看」，不是 review 紀錄。

**這一步審的是「有沒有照使用者的指示存、存進去的東西合不合第二大腦的規矩」，不是重審報告本身的技術結論。** 報告的品質在 P0x 的 Step 3 已經審過了。

## 驗證項目

| 項目 | 結果 | 備註 |
|------|------|------|

1. **指示遵循度**：使用者在 PR 留言裡講了「存什麼／怎麼呈現／怎麼存」。實際寫入的檔案、分類位置、章節結構、詳略程度，是否逐項對得上他講的？**他沒講到的部分才由你判斷；他講了的部分照做，不要自作主張換位置或換寫法。**
2. **規則來源正確**：格式與結構規則是否來自 `$WORK/index.md` 的「使用規則」，而不是憑記憶或照抄本 repo 既有檔案的樣子？
3. **不複製報告內文**：分析報告本體是否留在 LearnGhAgent、只以 GitHub URL 參照？寫進第二大腦的是否只有結論、理由、值得記住的機制？**整段搬運報告內文是最常犯的錯。**
4. **溯源完整**：`sources[]` 是否同時含分析報告的 GitHub URL 與 PR 網址？`author` 是否標成 `process:learn-gh-agent`？
5. **信任狀態誠實**：是否 `status: draft` 且**沒有**填 `verified`？（產出者是 AI，這是鐵則，不因為使用者叫你存就升級）
6. **時間座標**：主題檔是否在對應日期的日誌留了一條相對路徑連結？沒有連結的主題檔是孤兒，`validate.py` 會擋。
7. **log.md 只增不減**：是否只在最上面加新的日期區塊？**既有記錄一個字都不能改**——MyBrain 的 CI 有 append-only 檢查，改了會紅燈。
8. **index.md 沒有手寫**：各層 `index.md` 是否由 `reindex.py` 重生，而非手工編輯？
9. **驗證有跑且無 error**：`reindex.py` 與 `validate.py` 是否都執行過？`validate.py` 是否無 error（warning 可放行）？
10. **無密鑰洩漏**：寫入內容是否確實不含任何 token、API key、密碼、他人個資？**這一項有疑慮就直接 FAIL，不要放行。**
11. **log 格式合規**：4 個 section 是否齊全且順序正確？最後一行是否為 `MYBRAIN_PR:` 標記？長度是否在 3000 字內？

## 判定

- 第 10 項有疑慮 → 一律 `VERDICT: FAIL`
- 判定「不值得存」而沒開 PR，只要理由成立且第 11 項合規 → `VERDICT: PASS`（不開空 PR 是正確行為，不是失敗）
